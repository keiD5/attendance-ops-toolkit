# 보안 모델

작은 근태/승인 시스템을 위한 일반적인 보안 모델입니다.

## 데이터 등급

- 공개 문서: 도움말, 지원 안내, 개인정보 처리방침처럼 외부 공개 가능한 문서
- 내부 문서: 직원 안내, 업무 흐름 메모, 내부 점검표
- 개인 사용자 데이터: 이름, 연락처, 휴가 요청, 출퇴근 기록
- 제한된 관리자 데이터: 역할 설정, 백업, 비밀번호 재설정 흐름, 보안 로그
- 비밀값: API 키, 개인 키, 토큰, 서명 키

## 역할 등급

- 직원: 자기 요청을 만들고 볼 수 있습니다.
- 승인자: 정해진 범위 안에서 요청을 승인할 수 있습니다.
- 운영자: 정책 범위 안에서 운영 기록을 관리할 수 있습니다.
- 소유자: 시스템 전체 설정과 복구 작업을 관리할 수 있습니다.

## 규칙

- 표시 이름만으로 권한을 판단하지 않습니다.
- 숫자 사용자 ID만으로 권한을 판단하지 않습니다.
- 소유자 전용 기능은 소유자 역할 확인이 필요합니다.
- 위임 권한은 과도하게 번지지 않는지 테스트해야 합니다.
- 공개 호스팅과 API 보안은 따로 검토해야 합니다.

## 부정 테스트

배포 전 아래를 확인합니다.

- 직원이 관리자 데이터를 볼 수 없는가
- 승인자가 비밀번호를 재설정할 수 없는가
- 운영자 권한이 소유자 설정을 바꿀 수 없는가
- 일부 기록 누락이 전체 사용자 목록 삭제로 이어지지 않는가
- 오래된 배포 폴더가 공개로 노출되지 않는가

## 쉬운 비유

이름표가 `사장`이라고 적혀 있다고 금고를 열어주면 안 됩니다.

진짜 열쇠가 있는지, 그 열쇠가 어떤 문까지 여는지 확인해야 합니다.
